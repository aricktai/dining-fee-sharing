# Product Specification

## 功能
- 日期、時間、餐廳、總餐費、小菜總額
- A/S/E/J/P 人員選擇
- 平均分攤
- 個別金額
- 單一付款人
- 多人付款
- 即時差額
- 自動計算誰欠誰
- 目前位置
- OSM 附近餐廳
- Google Maps
- ⭐ 常用地點
- 今日紀錄
- 歷史紀錄
- 歷史登入
- 歷史搜尋
- 歷史單筆刪除
- transfer 個別結清、結清方式與結清日期
- 歷史紀錄結清狀態及全部／待結清／已結清篩選

## 附近餐廳
附近餐廳維持使用 OpenStreetMap / Overpass。單一 endpoint 發生 HTTP 5xx、network error、timeout 或無效回應時，應有限次自動 fallback；過程不顯示連續錯誤，全部 endpoints 失敗後才顯示一次友善訊息，且不得清除已取得的定位。

## 個別金額
選擇後「個人主餐」欄位必須為空白，不得自動帶入平均金額。系統顯示每人的「小菜/人」，並自動以「個人主餐 + 小菜/人」算出應付金額。

小菜總額已包含於總餐費；平均分攤仍只以總餐費除以人數。小菜為空白或 0 時視為 0。

Example:
總餐費 NT$500、小菜 NT$60
A 主餐=100, S 主餐=200, E 主餐=空白

顯示：
`應付合計：NT$360 / 總餐費：NT$500 / 尚差：NT$140`

## 多人付款
同樣即時計算付款合計與總餐費差額。

付款人與用餐人員是獨立概念：participants 只決定誰需分攤餐費，付款人則可從固定 A/S/E/J/P 全員選擇，即使未參與本次用餐也可付款。單一付款人預設為 S，多人付款仍可由任意固定成員共同付款。

## 結算
Balance = paid - owed
正值為應收，負值為應付。

結算會納入固定 A/S/E/J/P 全員；非 participant 的 owed 為 0，其 paid 仍會產生應收與對應 transfer。

每筆新 transfer 預設未結清；整筆狀態由 transfers 推導為 `unknown`、`unsettled`、`partial`、`settled` 或 `not_required`。舊 transfer 未含結清欄位時顯示「⚪ 未記錄」，不視為欠款；第一次操作時才將整組 transfers 升級為新格式。

## 歷史
匿名只能操作今日資料；authenticated 可查看與管理完整歷史。匿名儲存非今日紀錄時必須先登入；登入成功後自動繼續原本儲存，登入失敗、取消或 token 過期重新登入時都必須保留表單內容。

## V4.0 個人虛擬錢包
- A/S/E/J/P 各自擁有可跨用餐持續使用的獨立錢包，可儲值、人工調整並查看最近 50 筆交易。
- 錢包允許負餘額；結清前顯示目前餘額、扣款及扣款後餘額，負數僅提醒、不阻擋。
- 歷史 transfer 可選現金或付款者本人的錢包；receiver wallet 不增加，且不支援代付。
- 已結清 transfer 必須先取消（wallet 會建立 reversal）後才能改用另一方式。舊 settled transfer 缺少 method 時顯示「未記錄」。

## V4.0.1 操作簡化
- 首頁 wallet summary 位於儲存按鈕之後、今日紀錄之前，只顯示五人餘額與錢包管理入口。
- 歷史紀錄不提供「全部以現金結清」；每筆未結清 transfer 個別選擇現金或付款者錢包。
- 已結清 transfer compact 顯示狀態、方式與日期，並保留低視覺優先級的取消結清入口。
